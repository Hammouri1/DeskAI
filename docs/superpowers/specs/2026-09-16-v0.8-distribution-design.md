# V0.8 — Extensibility and Distribution: design

Date: 2026-09-16. Agreed with the owner in conversation ("for now yes" to the plan below,
with two scope answers the same day: DeskAI is distributed as a **zip on GitHub Releases**,
and add-ons (plugins) are **not built** until the system is finished).

## What V0.8 delivers

1. **GitHub builds and tests every push and pull request** (`.github/workflows/build.yml`):
   restore, Release build, all tests, `dotnet format --verify-no-changes`, and
   `dotnet list package --vulnerable --include-transitive`, which fails the run if any
   dependency has a known vulnerability.
2. **A release zip for each tag** (`.github/workflows/release.yml`, on `v*` tags): the app is
   published self-contained for x64 with the tag as its version, zipped as
   `DeskAI-<version>-win-x64.zip`, listed in a software bill of materials (CycloneDX JSON made
   by the `CycloneDX` .NET tool in CI only), and both are attached to a GitHub Release. No
   code signing: a certificate costs money; SignPath and Azure Trusted Signing are recorded
   as the options for later. Windows may warn about an unknown publisher on first run, and
   `docs/INSTALL.md` says so plainly.
3. **No self-update.** DeskAI never checks online for a new version. Its only network use
   remains the AI service a person chose. Privacy and AI shows the version it is, and
   `docs/INSTALL.md` says where releases are.
4. **Back up and restore** on Privacy and AI. "Save a backup file…" writes a JSON file the person
   chose in the Windows save dialog holding their **rules and saved searches** and nothing else:
   no folders, no permissions, no AI settings, no keys, no paths. "Restore from a backup file…"
   reads a file the person chose, shows what would be added and what would be skipped and why
   (a name already in use; a rule the file describes that DeskAI cannot use), and only Restore
   adds. **Restored rules arrive switched off**, like starter packs, so a backup can never move
   a file by being restored. Every rule goes through the same `RuleCodec` and factories a typed
   rule does; a file is untrusted input.
5. **Start fresh** on Privacy and AI: after a dialog, DeskAI forgets everything it remembers:
   every connected folder and its permissions, index, and tidy history; every rule and saved
   search; the AI choice and every saved key; check history and settings; the look and the
   wallpaper memory. **No file on disk is touched**; tidied files stay where they are. This
   is what a person does before uninstalling, and it is the data-retention control V1.0 asks for.
6. **Accessibility check** as a test: every button without visible text, and every text box,
   password box, combo box, search box, and switch in the page files carries an automation
   name or a header. Plus the keyboard and Narrator steps already in `MANUAL-TESTING.md`.
7. **Crash recovery** is recorded rather than built: the interrupted-tidy recovery (ADR 0022),
   the startup-failure window, and the contained unhandled-exception handler already exist.
8. **Performance probe**: an opt-in test (`DESKAI_PERF=1`) that generates a few thousand
   files and times connect, refresh, search, and a tidy preview; the numbers are recorded in
   `docs/PERFORMANCE.md`. It never runs in the ordinary suite, so it cannot be flaky there.
9. **Localization**: V1 ships in English only. Dates, numbers, and sizes already format through
   the current culture. Moving strings to resource files is deferred and recorded in ADR 0030.
10. **Privacy review**: `docs/security/2026-09-16-v0.8-privacy-review.md`, every place data
    leaves the app or is written to disk, including the backup file and the CI logs.
11. **Add-ons**: not built. ADR 0030 records what an add-on could ever be allowed to do
    (classify, suggest a category, enrich search) and what it never could (touch a file, a
    setting, the network, or a key), so a later design starts from the boundary, not the feature.

## Tests

- `BackupPageTests`: export writes rules and searches and no folder, path, key, or setting;
  restore preview adds nothing; restore adds with new IDs, rules Off, names already used
  skipped and named; a second restore adds nothing; a malformed, oversized, or wrong-version
  file is refused in plain words; a rule with a hostile destination or unknown condition in the
  file is skipped with a reason; pins are kept only while there is room.
- `FreshStartPageTests`: after Start fresh nothing is connected, no rule, search, key, AI
  choice, check history, or wallpaper memory remains, the background icon is gone, and every
  generated file is exactly where it was.
- `AccessibilityNameTests`: the XAML rule above.
- `SettingsPageTests`: the version line.

## Manual steps

Added to `MANUAL-TESTING.md`: the backup dialogs, restoring on a second machine or profile,
Start fresh followed by a look at Credential Manager and `%LocalAppData%\DeskAI`, and the
first run of a release zip.
