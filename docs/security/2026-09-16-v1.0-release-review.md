# V1.0 release review — 2026-09-16

The final pass before calling DeskAI stable: every threat scenario the project has named is
traced to the control that stops it and the automated test that proves the control, the
accessibility and keyboard checks are recorded, and the install/uninstall/data-retention
behaviour is stated. Where only a person can verify something, the manual list is named.

## 1. The scenarios `INTERVIEW-NOTES.md` asks to whiteboard

| Scenario | Control | Tests |
| --- | --- | --- |
| The model proposes `..\..\Windows` | Schema parse may accept it; `WindowsPathPolicy` and `PlanValidator` block containment and protected paths; the executor re-checks | `PlanValidatorTests`, `PlanSafetyCheckTests`, `TidyAiTests`, `StructuredSuggestionParser` tests in `DeskAI.AI.Tests` |
| A junction escapes the root | Scanner and executor refuse reparse points on every component | `WindowsMetadataScannerTests`, `FolderTidyExecutorTests`, `TidyRunTests` (link after the list) |
| A destination appears after the preview | `overwrite: false`, per-file re-check at execution | `FolderTidyExecutorTests`, `TidyRunTests` (name taken) |

| The person asks to delete | No delete command exists; templates undo only empty made folders | `PlanValidatorTests`, `FolderTemplateServiceTests`, `FolderTidyExecutorTests` |

## 3. Data leaving the computer

Only the AI service the person chose, only after the dialog and Send, only the fields allowed
(`TidyAiTests`, `AiJourneyTests`, `CloudSuggestionProviderTests`, the request builder tests). No
telemetry, no update check, no DeskAI server (ADR 0030; `docs/security/2026-09-16-v0.8-privacy-review.md`).

## 4. Accessibility and keyboard

- `AccessibilityNameTests`: every icon-only button and every input in the page files carries a
  name or a header.
- Colour never carries state alone: every pill and badge has an icon and a word
  (`ShellLayoutTests`, `StatePillTests`, `DeskLookCatalogTests` for contrast on every look).
- High contrast maps every DeskAI token to a Windows system colour, including the new tints.
- Keyboard, focus, and Narrator are checked by hand: each list in `MANUAL-TESTING.md` ends with
  a Tab-through and a Narrator step. **The owner has not yet walked the V0.7–V0.9 lists**; that
  is the open item in `HANDOFF.md`.

## 5. Install, update, uninstall, data retention

- Install is unzip-and-run; nothing is written to Program Files, the registry, or startup
  (`NeverStartsWithWindowsTests`; ADR 0030; `INSTALL.md`).
- Update is replacing the folder; data lives in `%LocalAppData%\DeskAI` and Credential Manager.
- Uninstall is Start fresh (`FreshStartPageTests`: every folder, rule, search, key, setting, and
  memory gone; no file touched) then deleting the folder. Disconnecting a folder erases
  everything about it (`SqliteAuthorizedRootRepositoryTests`, `SqliteFileIndexTests`).
- Check history is bounded to 50 runs; nothing else grows without bound but the journal, which
  is the audit trail and is erased per folder on disconnect.

## 6. No placeholder UI presented as complete

`NoPlaceholderUiTests` scans the page files for "coming soon", "not implemented", "TODO",
"placeholder", and "lorem". The two disabled switches on Privacy and AI ("Text inside files —
not available", "Images inside files — not available") are honest statements of what does not
exist and are disabled, not placeholders.

## 7. Residual risks accepted for 1.0

- Unsigned zip until a certificate exists.
- The real `SystemParametersInfo` wallpaper call and the real theme repaint are only
  manually verifiable (recorded fakes in tests by design).
- A Windows notification may not appear on an unpackaged app; the in-app notice always does.
- Unattended tidying is bounded by design, not by a second process; a wrong rule can still move
  up to 25 files per check until the person turns it off or a stop condition fires. Undo covers
  every run.
