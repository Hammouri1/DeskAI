# V0.3 AI and Privacy Security Review

- Date: 2026-09-08
- Scope: optional sample-metadata AI advice, local/OpenRouter transport, disclosure, credentials, and limits
- Result: accepted for generated sample advice; real-folder AI disclosure remains disconnected

## Threats and Controls

- Prompt injection in names: serialized inside labeled untrusted data; output has no command/action vocabulary.
- Invented or malicious output: exact schema/version, response bytes/count, duplicate-property/ID, requested-ID, enum, confidence, and reason validation.
- Filesystem escalation: AI projects reference Core contracts only and receive no scanner, path, shell, executor, approval, or journal service.
- Excess disclosure: protected IDs are removed before candidates; every optional field follows the saved category set; cloud router rechecks the set.
- SSRF/provider switching: local URLs must be loopback; the OpenRouter HTTPS address is fixed; redirects and fallback are disabled. Only the model name is configurable.
- Secret exposure: key stored in Windows Credential Manager, PasswordBox cleared, database stores only reference, logging redacts provider-key labels.
- Unbounded cost/resources: request/response/file bounds, timeout, cancellation, no retry, and atomic daily cloud-request cap.
- Misleading success: provider status distinguishes disabled, offline, authentication, rate/quota, timeout, cancellation, malformed, safety rejection, cap, and provider error.

## Deferred Gate

The current AI button uses generated demo metadata only. Sending any user-selected folder metadata, extracted text, or images requires a new disclosure review, protected-item integration, UI preview of the exact real request, and additional tests. AI output still cannot directly construct executable operations.
