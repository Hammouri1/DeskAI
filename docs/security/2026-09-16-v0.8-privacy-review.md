# V0.8 privacy review — 2026-09-16

Scope: every place DeskAI writes data outside its own database, sends data off the computer,
or receives data from outside, as of V0.8 (backup and restore, Start fresh, GitHub builds and
releases). Threat model: a person's rules and saved searches may name things they would not
want published; a backup file may be edited by hand or by something else on the computer; CI
logs are public on a public repository.

## Where data goes

| Channel | What | When | Control |
| --- | --- | --- | --- |
| SQLite, `%LocalAppData%\DeskAI\deskai.db` | Connected folders (canonical path, permissions), index rows (root-relative paths, names, sizes, dates, categories), plans and journal, rules, saved searches, AI settings without the key, check history and settings, look, wallpaper memory | As before | Start fresh erases all of it in one press; disconnecting a folder erases that folder's rows. |
| Windows Credential Manager | One key per AI service, under `DeskAI/<service>` | When a key is saved | Removed per service on the page; every service's entry removed by Start fresh. Never in the database, logs, or a backup. |
| **The backup file** (new) | Rule names, conditions, and destinations; saved-search names and phrases; whether a search was pinned; a version number and a timestamp | Only when the person presses "Save a backup file…" and picks a location in the Windows save dialog | Nothing else is in it: `BackupService` takes only the rule and saved-search repositories and a clock (a test asserts it). No folder path, no permission, no index row, no AI setting, no key. A rule's destination is a folder name relative to a connected folder, never an absolute path. |
| The AI service the person chose | As before: at most file type, size and date, and name, after the dialog and Send | Unchanged | Unchanged (ADR 0020). |
| Windows wallpaper | Unchanged | Unchanged | Unchanged (ADR 0029). |
| GitHub Actions logs (new) | Build output and test names on a public runner | Every push | Tests generate their own data under the runner's temp folder and never touch a personal folder; no key exists on the runner; `dotnet list package --vulnerable` prints package names only. Nothing from a developer's machine reaches the runner but the repository. |
| GitHub Releases (new) | The published zip and the software bill of materials | On a tag | The zip contains the build output only; the bill of materials lists package names and versions. |

## Where data comes from

| Channel | What | Control |
| --- | --- | --- |
| **Restoring a backup file** (new) | A `.json` file the person picked in the Windows open dialog, at most 1 MB | Read read-only through `UserFileStore`, which refuses a network path, a relative path, a non-`.json` extension, a link, and an oversized file before opening. Parsed strictly (unknown fields refuse the file; a newer version refuses the file; more than 200 items refuses the file). Every rule is rebuilt through `RuleCodec` and `AutomationRule.Create` and every search through `SavedSearch.Create`, so a hand-edited destination such as `..\Windows` or an unknown condition kind is skipped with a reason. **A restored rule is always switched off**: the on/off flag is not in the file at all. A name already in use is skipped, never replaced. The preview shows every line and reason before Restore. |
| The AI service's reply | Unchanged | Unchanged (strict parser, ADR 0011). |

## What Start fresh does and does not do

Does: disconnects every folder (which cascades to index, permissions, plans, journal), removes
every rule and saved search, resets the AI choice and removes every catalog service's key,
clears check history and settings (so keep-running-when-closed is off and the icon goes),
resets the look, forgets the remembered wallpaper. Does not: move, rename, or delete any file;
change the wallpaper Windows is showing; touch anything outside `%LocalAppData%\DeskAI` and
the `DeskAI/*` credential entries. `FreshStartService` holds no scanner, reader, executor,
journal, or wallpaper setter (a test asserts it).

## Checked and not accepted

- Putting connected folders or their permissions in a backup: refused. A permission is given
  through the Windows picker and re-checked live; carrying it in a file would make a file a
  grant.
- Putting the AI key or the AI service choice in a backup: refused. A key never leaves
  Credential Manager; a service choice without its consent dialog would skip the disclosure.
- Restoring rules switched on: refused. A file could then move files by being restored.
- Checking GitHub for updates from inside the app: refused (ADR 0030). The only network use
  stays the AI service the person chose.
- Telemetry, crash reporting to a server: not added. Logging stays local and redacted.

## Residual risks

- A backup file is plain JSON on the person's disk. Rule names and search phrases are readable
  by anything that can read that file. The page says what the file holds and does not hold, and
  the person chooses where it goes.
- The release zip is unsigned until a certificate exists (ADR 0030). `INSTALL.md` tells people
  to download only from the Releases page.
- `dotnet list package --vulnerable` depends on the NuGet advisory feed being reachable from the
  runner; if the feed is down the step fails closed rather than passing.
